    - src/core/MT5/tck/: TckModels (TkcTick, TkcInfo, TkcException), TkcDecoder (static; `.tkc` → `(TkcInfo, IReadOnlyList<TkcTick>)`), TkcFile (lazy wrapper + TkcRepository.ListSymbolFiles). Decoder for MetaTrader's local monthly tick-cache files. See ARCHITECTURE §20.

The Requester subtab drives `Mt5TickService.SyncTicksRangeAsync`. Known inconsistency: file lives under `src/core/MT5/` even though its namespace is `backs2.ViewModels`; it belongs with the other `Mt5TickViewModel` partials under `src/gui/MT5/`.
    - src/core/Writers/: Mt5TickWriter.cs (contains Mt5TickWriter + Mt5TickStreamWriter). The folder exists for writers that do not fit the standard CacheEnvelope<KlineCompact[]> shape used by every provider. CacheManager remains the writer for all Kline data.
    - src/core/Utils/: small stateless helpers that do not justify their own feature folder. Criteria: pure functions, no DI, no logging, no state, cross-cutting. Currently EasternTime (DST-aware Eastern Time conversion for Unix-ms UTC timestamps). See src/core/Utils/README.md for the inclusion rule.

    - src/core/DataAutomation/AnalysisService.cs: parsed-JSON diagnostics. Timezone-aware gap classification (expected Session/Weekend/Holiday vs. TimeUnexpected), PriceGap, VolumeSpike. Supersedes the removed `docs/analyze-parsed.ps1`.

Grid cap at 100k rows; `PopulateGrid` toggle skips the DataGrid bulk-insert on large fetches while CSV streaming continues.
    - Logging: static LogManager in src/core/LogManager.cs. Sole static in the codebase. Initialized in Program.Main before Avalonia. Tagged severity API: Info / Debug / Warn / Error. No filtering.

    - Monte Carlo: time-domain block bootstrap. See ARCHITECTURE §17 (engine) and §14 (tab). Iteration cap 100,000; curve retention ceiling 100,000,000 cells; real cancellation via CancellationToken.
    - Compute Worker: Phase 1 infrastructure. See ARCHITECTURE §21.
    - Data Automation: three subtabs. Extraction captures TradingView screenshots into data/shots/. Parsing OCRs them into data/parsed/. Analysis reads a parsed file and reports problems. See ARCHITECTURE §18.
    - MT5 Tick Bridge: MQL5 Expert Advisor at docs/Backs2TickBridge.mq5 (v1.18) connects out to a C# TcpListener on 127.0.0.1:5555. Tick data lands in a DataGrid and streams to CSV at data/ticks/. See ARCHITECTURE §19.
    - MT5 History Requester: MQL5 action `SYNC_TICKS_RANGE` (v1.17+). Forces the terminal to download a specific tick range from the broker and write it into the local `.tkc` cache, iterating day-by-day. Emits PROGRESS frames and an immediate ack; the C# side scales its request timeout by the range span. Latest-wins: a new chunked request pre-empts an in-flight one.
    - MT5 .tkc Extraction: reads MetaTrader's local monthly tick-cache files under {TerminalDataRoot}\bases\{Broker}\ticks\{Symbol}\YYYYMM.tkc, decodes them, aggregates to a TimeframeMap.All timeframe, writes kline cache as source "MT5 Parsed". No EA, no TCP — pure file I/O. See ARCHITECTURE §20.

- Crucial Rules:
    - Never modify MainWindow.axaml namespace without updating views xmlns.
    - All ViewModels: public partial class inheriting ObservableObject.
    - New services registered in App.axaml.cs -> ConfigureServices.
    - Async-first: disk and network I/O use Task-based patterns.
    - No new for core services; inject via constructor.
    - LogManager is the only static class allowed. Never register it in DI. Never pass it as a ctor parameter. Call the static API directly with a LogTag.
    - data/strategies/*.cs must never be compiled into the app (Compile Remove for data\**\*.cs in backs2.csproj).
    - logs/ and .env are git-ignored; never commit secrets or log output.
    - Strategy parameters live in the source file as `// @param` lines. They must be above any `using` directives — the parser stops at the first non-comment, non-blank line.
    - Preset filenames encode the strategy name.
    - Account JSON filenames encode the firm name. One firm per file.
    - Active account is set only via `AccountService.SetActive`.
    - The SelectionQueue is the source of truth for enabled datasets. No parallel enabled-state anywhere else.
    - Queue persistence is `"symbol@timeframe"` strings in `settings.json`.
    - Monte Carlo operates in the time domain. Never scramble trades. Use `TimeSlice[]` from `TimeSliceBuilder`. Compound as flat-bet absolute PnL, not percentages.
    - Monte Carlo iteration cap: `MonteCarloEngine.MaxIterations = 100_000`. Enforced by the UI NumericUpDown `Maximum`, a ViewModel guard that refuses to start, and the engine's own clamp. Never raise it without re-validating CPU saturation and the curve retention ceiling.
    - Monte Carlo curve retention ceiling: `MonteCarloEngine.MaxCurveCells = 100_000_000`. Above it, `retainCurves = false`, `SimulateOnce` receives a `null` curve, and `MonteCarloResult.CurvesRetained` is false. The stats panel surfaces a `MEMORY` section and the equity-curve plot shows the retention-limit message. All scalar stats still populate.
    - Monte Carlo cancellation: `MonteCarloEngine.Run` takes a `CancellationToken` (default `default`); the token flows into `ParallelOptions.CancellationToken`. `MonteCarloViewModel.RunAsync` owns the CTS; `CancelCommand` fires it. Partial results from datasets that completed before cancel are kept. Never remove the cancellation param.
    - Position size defaults to 1.0 in `Trades.Enter`. Strategies that need a different size pass it explicitly.
    - ScottPlot's `UserInputProcessor` is disabled on every `AvaPlot` in the app. Mouse drag cannot pan or zoom. Pan/zoom is keyboard-only: arrow keys pan 10% of the visible span, `+`/`-` zoom the X-axis by 10%. Plots are `Focusable="True"`. Never re-enable `UserInputProcessor` — the drag state could get stuck on some driver configurations.
    - The Monte Carlo trade-cluster plot dispatches `NavigateToTradeMessage` via `WeakReferenceMessenger.Default`. Receivers are `MainViewModel` (switches the Chart tab) and `ChartViewModel` (selects dataset, scrolls to timestamp). Never wire cross-tab navigation through direct ViewModel references; use the messenger. Navigation does not mutate the SelectionQueue — an unqueued target produces a status-line warning.
    - `KMeansClusterer.Cluster` is deterministic (fixed RNG seed). Do not change the seed — the same trades must produce the same clusters on every render.
    - Compute worker: process-isolated infrastructure in `src/core/Compute/`. The worker is `backs2.exe --worker`, dispatched in `Program.Main` before Avalonia or LogManager initialize. It writes nothing to `logs/`; diagnostics go to `Console.Error` and are captured by the parent as `[worker <pid> stderr]` Debug lines. Do not add DI registration for the worker side, and do not introduce Avalonia dependencies in the worker path.
    - Compute worker IPC uses length-prefixed JSON frames over anonymous pipes (`WorkerIpc`). Anonymous-pipe directions are load-bearing: `serverOut` is parent-writes/worker-reads and maps to the worker's `--in`; `serverIn` is parent-reads/worker-writes and maps to the worker's `--out`. Swapping them causes immediate EOF on the worker side.
    - Compute worker memory cap uses Win32 Job Objects (`JobObjectHandle`) with `JOB_OBJECT_LIMIT_PROCESS_MEMORY`. Non-Windows platforms degrade gracefully (attach returns false with a Warn log). Never raise the cap silently; the caller passes `JobConfig.MemoryLimitMb` explicitly.
    - Data Automation captures via PrintWindow with PW_RENDERFULLCONTENT; do not switch to DXGI Desktop Duplication (returns black on Chromium windows).
    - Automation input uses SendInput via P/Invoke. Never hook input. Never use H.InputSimulator or InputSimulatorStandard.
    - Calibration persists to config/data_automation.json. Per-field regions (DATE, TIME, O, H, L, C, V) plus a click point. Only O/H/L/C/V are required to enable Start Automation.
    - Mixed-DPI: the calibration overlay is re-fitted on ScalingChanged; its final RenderScaling is the authoritative factor for coordinate conversion. Do not use Screens.ScreenFromPoint for this.
    - Screenshots land in data/shots/ as {symbol}_{timeframe}_{index:D4}_{field}.png. One file per field.
    - Data Automation hosts three subtabs (Extraction / Parsing / Analysis). Parsing runs out-of-process via OcrWorkerHost; never inline ONNX inference on the UI thread.
    - OCR parsing rejects are written to data/parsed/{symbol}_{timeframe}_misses.txt. The Extraction tab's "Re-extract Missing" consumes that file verbatim — do not introduce a parallel miss list.
    - Analysis runs in-process via AnalysisService. The standalone docs/analyze-parsed.ps1 has been removed; do not resurrect it.
    - MT5 tick bridge uses raw TCP sockets (BCL `System.Net.Sockets`). Never add ZeroMQ or any other IPC dependency. The MQL5 EA is a TCP **client** that connects out to a C# `TcpListener` — MQL5 does not implement server-side sockets.
    - MT5 tick data is NOT an `IDataProvider`. It does not fit the `List<Kline>` contract. Consumed only by `Mt5TickService` and the MT5 Ticks tab.
    - `src/core/Writers/` holds writers that do not fit the standard `CacheEnvelope<KlineCompact[]>` shape. Today: `Mt5TickWriter.cs` (both the buffered `Mt5TickWriter` and the streaming `Mt5TickStreamWriter`). Do not move `CacheManager` there.
    - All MT5 fetch parameters (symbol, lookback, target, chunk/batch size) come from C#. The EA has no inputs — host/port/timeout/cap are `#define` constants. Edit both sides if the port changes.
    - MT5 must whitelist `127.0.0.1` in Tools → Options → Expert Advisors → "Allow WebRequest for listed URL". The WebRequest list governs `SocketCreate`/`SocketConnect`. Do not skip this.
    - MT5 EA serialization must use the `uchar[]` byte-buffer path. Never use MQL5 `string` concat (`+=` or `StringAdd`) on the hot path — both reallocate on every append and are O(N²).
    - MT5 `CopyTicks` `from_msc` is inclusive. Never send `next_from_msc = lastMsc + 1` — it drops same-ms ticks at every seam. Send `next_from_msc = lastMsc` and dedupe the trailing same-ms count on the next slice (see ARCHITECTURE §19).
    - MT5 prewarm is per-symbol per-process. `Mt5TickService.PrewarmAsync` is idempotent via `HashSet<string> _warmedSymbols`. Do not bypass it — first `CopyTicks` per symbol costs ~2× warm.
    - MT5 `onBatch` is awaited inside the fetch loop. Do not change it to a fire-and-forget write — the deliberate backpressure is what bounds memory.
    - MT5 `CountTicksAsync` uses an adaptive timeout: `Mt5TimeoutMs + min(spanDays, 90) × 3000 ms`. The base timeout is sized for fetch batches, not range queries — a 30-day query takes ~44 s.
    - MT5 `SyncTicksRangeAsync` uses a **span-scaled** timeout: `Mt5TimeoutMs + clamp(spanDays × 500 ms, 20 min, 60 min)`. Never reuse the COUNT_TICKS formula for SYNC, and never send a fixed-timeout SYNC request.
    - MT5 `HandleSyncTicksRange` must emit an immediate-ack PROGRESS frame on accept, throttle bypassed. The first `CopyTicksRange` call can block for minutes on a cold symbol; without the ack the C# side times out on a live request. Do not remove this ack.
    - MT5 `Mt5TickServer.TryParseProgress` must accept BOTH PROGRESS shapes (`cumulative_ticks` for COUNT_TICKS; `synced_days`/`skipped_days` for SYNC). None of the three is mandatory — a missing field means "not applicable for this action".
    - MT5 grid cap: `Mt5TickViewModel.MaxGridRows = 100_000`. `PopulateGrid` auto-unchecks once the cap is hit; `TargetTicks > 500_000` auto-unchecks at entry. Never raise the cap without re-validating the DataGrid freeze behavior — the freeze was a `Reset`-per-batch storm, not a memory issue.
    - MT5 tick CSV parsing builds bars from `Bid`, `Volume` = tick count. Zero-bid ticks are dropped. Cache source is `MT5 Parsed`. The parse runs inside `Task.Run` — never inline on the UI thread.
    - MT5 timeframe bucketing is epoch-relative: `(timeMsc / tfMs) * tfMs`. Never re-introduce per-hour anchoring — it breaks 45m.
    - `data/ticks/` is git-ignored (user-fetched data, same class as logs/).
    - MT5 `.tkc` decoding lives in `src/core/MT5/tck/`. Decoder must not emit per-day/per-block logs — exactly one `Info` line per file (`TKC 'file': N ticks, D day(s), T ms`) and one `Warn` at the end if zero-bid ticks were dropped. Anything more is spam that buried the 0-tick bug for hours.
    - MT5 `.tkc` decode must be serial across files (never parallel). Peak memory is bounded by the largest single file's tick list + the bucket dict. Parallel decode would hold all files' ticks simultaneously (~3.6 GB for a full-history GOLD.pro set).
    - MT5 `.tkc` decode iterates files newest-first and ticks within a file in reverse. This lets `TkcLookbackDays` and `TkcMaxTicks` stop the decode mid-file without holding all ticks. Bucket semantics under reverse iteration: first bid seen = Close, last bid seen = Open.
    - MT5 `.tkc` value offset within a 16-byte record is per-block (first half or second half). Detect it by sampling; never hard-code.
